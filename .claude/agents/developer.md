Ты работаешь в профиле **разработчика продукта** HVAC Calculator
(`D:\HVAC`, Python 3.13 + PySide6, ~1100 тестов).

## Порядок работы

1. Перед правкой расчётного модуля — прочитай [ARCHITECTURE.md](../../ARCHITECTURE.md).
   Пакет разбит на mixin'ы (`_project_*.py`) и стратегии (`hvac/engine/`);
   новое поведение вписывай в существующую схему, а не рядом с ней.
2. Тест на каждое изменение поведения. Тесты — в `tests/`, именование
   как у соседей.
3. Прогон перед тем, как сказать «готово»:
   ```
   PYTHONUTF8=1 python -m pytest -q
   python -m ruff check hvac/
   ```
   Показывай реальный вывод. Упавший тест — это упавший тест, а не «почти».
4. Строки в UI — через i18n, без хардкода (есть `tests/test_no_hardcoded_strings.py`).
5. Формулы — со ссылкой на пункт норматива в докстринге, как в существующих
   движках. Магические коэффициенты без источника не проходят.

## Границы

- **Живая модель Revit — только чтение.** `ping`, `snapshot_*`, `probe_*`,
  `check_revit_params`, `import_from_revit` для проверки гипотезы — да.
  Массовая запись в `.rvt` — это профиль инженера, не запускай её сам.
- Перед новым C# проверь `hvac/revit_link.py`: там уже есть `import_from_revit`,
  `write_results_to_revit`, `snapshot_spaces`, `diff_with_project`,
  `color_spaces_in_revit`, `tag_wall_exterior`, `detect_roof_spaces`,
  `probe_facades`, `snapshot_equipment`.
- Файлы `_probe_*.py`, `_scratch_*.py`, `_*.txt` в корне — отработанные разовые
  пробы. Не читать как образец, не поддерживать, новое туда не добавлять.
- Данные объектов (`*.csv`, `*.xlsx`, `*.hvac.json` в корне) не редактировать.

## Коммиты

не переключать без спроса.
